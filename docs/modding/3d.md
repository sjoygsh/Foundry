# 3D mods

**Status:** works as of M25. A content mod can add a lit, solid 3D object without code. A
native mod can keep 3D objects and lights in the host's scene, move them from a system, and
create collision bodies and characters, through the 28 calls `FoundryApi_v6` adds. Script
mods have no 3D calls yet.

This page was written from a mod built **outside** the Foundry checkout, against an installed
`foundry.h` and nothing else. Every command below was run, and every listing is the file that
ran. The header is the contract; the design is
[`design/public3d.md`](../design/public3d.md) and ADR-0059. Read
[`content-mods.md`](content-mods.md) and [`native-mods.md`](native-mods.md) first: this page
only adds what is specific to 3D.

Conventions are Foundry's everywhere (ADR-0048): right-handed, +Y up, −Z forward, metres,
radians, column-major 4×4 matrices, unit quaternions as `(x, y, z, w)`.

## What you build

One package, `beacon`, with two halves:

* **content only:** a stone pillar the sample draws and makes solid, from a glTF file, a
  material and one `sandbox3d:prop` record;
* **native, with the player's consent:** a second pillar in copper that turns, with a lamp
  above it and a box the player cannot walk through.

```
beacon/
  package/
    mod.fdt
    beacon.fdt
    models/
      pillar.gltf
      plinth.bin
  beacon.c
  install/               # written by the commands below
```

Keep `install/` beside `package/`, not around it: `fpack` refuses an output directory that
contains the package it is compiling.

## Before you start

You need an installed Foundry and the pinned Zig 0.16.0, which is also the C compiler.

```sh
cd /absolute/path/to/Foundry
zig build install -Drhi=metal -Doptimize=ReleaseSafe --prefix /absolute/path/to/runtime
FOUNDRY=/absolute/path/to/runtime
```

Use `-Drhi=vulkan` on Windows. The prefix holds everything a mod author needs:
`bin/fpack`, `bin/sandbox3d`, `include/foundry.h` and `content/*.fpk`. It can be moved, and
nothing below reads the checkout again except to borrow one model file.

## 1. The content half

`package/mod.fdt`:

```fdt
foundry:mod beacon:content {
    name     "Beacon"
    version  1
    license  "MIT"
    summary  "A stone pillar from content, and a turning lit one from C."
    requires [ { id sandbox3d:content } ]
    native   "beacon"
    abi      { min 6 max 6 }
}
```

`native` and `abi` belong to the native half; leave both lines out for a content-only mod.
`abi { min 6 max 6 }` says the library needs the v6 table, and a host that does not offer it
skips the library and keeps the content.

A model is authored as glTF 2.0. Any file with positions and normals will do; this guide
borrows one from the checkout so that nothing else has to be installed:

```sh
mkdir -p beacon/package/models && cd beacon
cp /absolute/path/to/Foundry/samples/sandbox3d/testdata/mods/plinth/models/plinth.gltf package/models/pillar.gltf
cp /absolute/path/to/Foundry/samples/sandbox3d/testdata/mods/plinth/models/plinth.bin  package/models/plinth.bin
```

The `.bin` keeps its name because the glTF refers to it by name.

`package/beacon.fdt`:

```fdt
# Two materials with authored IDs, so another package can override either look.
foundry:material beacon:materials.stone {
    shading foundry:shading.lit
    base_color { r 0.45 g 0.42 b 0.38 a 1 }
    roughness 0.9
}
foundry:material beacon:materials.copper {
    shading foundry:shading.lit
    base_color { r 0.85 g 0.35 b 0.12 a 1 }
    metallic 0.8
    roughness 0.3
}

# The glTF's one material is named "Stone"; bind it to ours instead of a generated one.
# `collision true` also compiles beacon:models.pillar.collision from the same triangles.
foundry:model_import beacon:models.pillar {
    source "models/pillar.gltf"
    collision true
    materials [ { name "Stone" material beacon:materials.stone } ]
}

# The content-only object: the sample draws every sandbox3d:prop and makes it solid.
sandbox3d:prop beacon:props.pillar {
    model beacon:models.pillar
    position { x -0.5 y 0 z 2.0 }
    collision beacon:models.pillar.collision
}
```

What each record does:

* **`foundry:material`** is a look. `foundry:shading.lit` reads `base_color`, `metallic`,
  `roughness` and the texture fields [`content-mods.md`](content-mods.md) lists. Giving it
  your own ID is what lets another mod replace it.
* **`foundry:model_import`** compiles the glTF into a `foundry:model` with the same ID, and
  its meshes. `materials` binds a glTF material **by name** to a material record; unbound
  ones get generated IDs (`…material0`). `collision true` also produces
  `beacon:models.pillar.collision`, a triangle mesh in the model's own space. The import
  converts nothing silently: a file in the wrong units or handedness is refused, not fixed.
* **`sandbox3d:prop`** is the *sample's* schema, not the engine's. It places a model at a
  position with an optional `yaw` (radians) and `scale`, and with `collision` makes it a
  static solid. A solid prop keeps scale 1: collision poses are rigid, so size is baked into
  the file. Another game will have its own record for this; the model and material are the
  parts that carry over.

Compile it against the packages it refers to:

```sh
mkdir -p install/beacon
"$FOUNDRY/bin/fpack" --out install/beacon.fpk --assets-out install/beacon \
    --dependency "$FOUNDRY/content/core.fpk" \
    --dependency "$FOUNDRY/content/sandbox3d.fpk" \
    package
```

```
fpack: beacon:content version 1 -> install/beacon.fpk (3261 bytes)
```

`install/beacon/models/pillar/` now holds `mesh0.fmesh` and `collision0.fcol`. Compiling the
same sources again gives the same bytes.

## 2. The native half

`beacon.c`:

```c
#include "foundry.h"
#include <math.h>
#include <string.h>

static const FoundryApi_v6 *api;
static FoundryMod self_mod;
static FoundryEntity pivot;
static FoundryInstance pillar;
static FoundryLight lamp;
static FoundryBody3D solid;
static FoundryBool stopped;
static FoundryBool checked;

static FoundryContentId id(const char *s) { return foundry_content_id(s, strlen(s)); }
static FoundryStr str(const char *s)
{
    FoundryStr out;
    out.ptr = (const uint8_t *)s;
    out.len = strlen(s);
    return out;
}
static void say(FoundryLogLevel level, const char *text)
{
    (void)api->log_write(self_mod, level, str(text));
}

/* Says which step was refused and with what code, then passes the code on. */
static FoundryResult refused(const char *step, FoundryResult result)
{
    say(FOUNDRY_LOG_WARN, step);
    (void)api->log_write(self_mod, FOUNDRY_LOG_WARN, api->result_name(result));
    return result;
}

static FoundryLight3D lamp_at(FoundryVec3 position)
{
    FoundryLight3D light;
    memset(&light, 0, sizeof(light)); /* reserved bytes and unused fields must be zero */
    light.kind = 1;                   /* point */
    light.color.x = 1.0f; light.color.y = 0.7f; light.color.z = 0.4f;
    light.intensity = 60.0f;          /* candela */
    light.range = 4.0f;               /* metres */
    light.outer_cone = 0.7f;          /* every kind needs inner_cone < outer_cone <= pi/2 */
    light.rotation.w = 1.0f;
    light.position = position;
    light.position.y += 1.6f;
    return light;
}

/* Runs once per fixed tick, never inside a frame. */
static void turn(void *ctx, const FoundryStep *step)
{
    FoundryMat4 world;
    FoundryTransform local;
    FoundryPose3D pose;
    FoundryLight3D light;
    float angle;

    (void)ctx;
    if (stopped) return;
    /* The host propagated the hierarchy before systems ran: read this tick's pose... */
    if (api->world_world_transform(pivot, &world) != FOUNDRY_OK ||
        api->world_transform_get(pivot, &local) != FOUNDRY_OK) goto refused;
    pose.position.x = world.elements[12];
    pose.position.y = world.elements[13] + 0.6f;
    pose.position.z = world.elements[14];
    pose.rotation = local.rotation;
    light = lamp_at(local.translation);
    /* ...move what we own to it... */
    if (api->render3d_instance_set_world(pillar, &world) != FOUNDRY_OK ||
        api->physics3d_body_set_pose(solid, &pose) != FOUNDRY_OK ||
        api->render3d_light_set(lamp, &light) != FOUNDRY_OK) goto refused;
    /* Once: a ray from above must now land on the box we own. */
    if (!checked) {
        FoundryVec3 above = pose.position;
        const FoundryVec3 down = {0.0f, -1.0f, 0.0f};
        FoundryFilter3D everything;
        FoundryRayHit3D found;
        FoundryBool hit = FOUNDRY_FALSE;
        memset(&everything, 0, sizeof(everything));
        everything.mask = UINT32_MAX;
        above.y += 2.0f;
        if (api->physics3d_raycast(above, down, 5.0f, &everything, &found, &hit) != FOUNDRY_OK) goto refused;
        if (hit && found.body.bits == solid.bits)
            say(FOUNDRY_LOG_INFO, "beacon: a ray from above lands on our box");
        checked = FOUNDRY_TRUE;
    }
    /* ...and write the next one. Time comes from the tick, never a clock. */
    angle = (float)(step->tick % 1440u) * (6.2831853f / 1440.0f);
    local.rotation.x = 0.0f; local.rotation.z = 0.0f;
    local.rotation.y = sinf(angle * 0.5f);
    local.rotation.w = cosf(angle * 0.5f);
    if (api->world_transform_set(pivot, &local) != FOUNDRY_OK) goto refused;
    return;
refused:
    stopped = FOUNDRY_TRUE;
    say(FOUNDRY_LOG_WARN, "beacon: a call was refused; the pillar stops turning");
}

static void release_all(void)
{
    if (solid.bits) (void)api->physics3d_body_destroy(solid);
    if (lamp.bits) (void)api->render3d_light_destroy(lamp);
    if (pillar.bits) (void)api->render3d_instance_destroy(pillar);
    if (pivot.bits) (void)api->world_destroy_entity(pivot);
    solid.bits = lamp.bits = pillar.bits = pivot.bits = 0;
}

FOUNDRY_EXPORT FoundryResult foundry_mod_init(FoundryGetApi get_api, FoundryMod self)
{
    const FoundryVec3 above = {-1.75f, 3.0f, 0.25f};
    const FoundryVec3 down = {0.0f, -1.0f, 0.0f};
    FoundryFilter3D everything;
    FoundryRayHit3D floor;
    FoundryBool hit = FOUNDRY_FALSE;
    FoundryTransform place;
    FoundryMat4 world;
    FoundryLight3D light;
    FoundryBody3DDesc box;
    FoundryCamera3D camera;
    FoundrySystemDesc system;
    FoundryResult result;

    self_mod = self;
    stopped = checked = FOUNDRY_FALSE;
    api = (const FoundryApi_v6 *)get_api(FOUNDRY_API_VERSION_6);
    if (api == NULL) return FOUNDRY_ERR_UNSUPPORTED;

    /* 1. Ask the collision world where the floor is. Queries are open to everyone. */
    memset(&everything, 0, sizeof(everything));
    everything.mask = UINT32_MAX;
    result = api->physics3d_raycast(above, down, 10.0f, &everything, &floor, &hit);
    if (result != FOUNDRY_OK) return result;
    if (!hit) return FOUNDRY_ERR_NOT_FOUND;

    /* 2. The floor belongs to the host. Changing it is refused, and nothing happens. */
    if (api->physics3d_body_destroy(floor.body) != FOUNDRY_ERR_REFUSED) return FOUNDRY_ERR_INTERNAL;
    say(FOUNDRY_LOG_INFO, "beacon: destroying the host's floor was refused, as it should be");

    /* 3. An entity with the engine's transform: the thing that turns. */
    memset(&place, 0, sizeof(place));
    place.translation = floor.point;
    place.rotation.w = 1.0f;
    place.scale.x = place.scale.y = place.scale.z = 1.0f;
    result = api->world_create_entity(&pivot);
    if (result != FOUNDRY_OK) return result;
    result = api->world_transform_set(pivot, &place);
    if (result != FOUNDRY_OK) { (void)refused("beacon: transform refused", result); goto fail; }

    /* 4. A retained instance of our model, wearing our second material in slot 0. */
    memset(&world, 0, sizeof(world));
    world.elements[0] = world.elements[5] = world.elements[10] = world.elements[15] = 1.0f;
    world.elements[12] = floor.point.x;
    world.elements[13] = floor.point.y;
    world.elements[14] = floor.point.z;
    result = api->render3d_instance_create(self, id("beacon:models.pillar"), &world, &pillar);
    if (result != FOUNDRY_OK) { (void)refused("beacon: instance refused", result); goto fail; }
    result = api->render3d_instance_set_material(pillar, 0, id("beacon:materials.copper"));
    if (result != FOUNDRY_OK) { (void)refused("beacon: material refused", result); goto fail; }

    /* 5. A retained point light above it. */
    light = lamp_at(floor.point);
    result = api->render3d_light_create(self, &light, &lamp);
    if (result != FOUNDRY_OK) { (void)refused("beacon: light refused", result); goto fail; }

    /* 6. A kinematic box the player cannot walk through. */
    memset(&box, 0, sizeof(box));
    box.shape.kind = 2; /* box */
    box.shape.half_extents.x = 0.6f; box.shape.half_extents.y = 0.6f; box.shape.half_extents.z = 0.6f;
    box.pose.position = floor.point;
    box.pose.position.y += 0.6f;
    box.pose.rotation.w = 1.0f;
    box.kind = 1; /* kinematic */
    box.layer = 1;
    box.mask = UINT32_MAX;
    box.user = id("beacon:solid").hash;
    result = api->physics3d_body_create(self, &box, &solid);
    if (result != FOUNDRY_OK) { (void)refused("beacon: body refused", result); goto fail; }

    /* 7. The camera can be read, not written. */
    if (api->render3d_camera_get(&camera) == FOUNDRY_OK)
        say(FOUNDRY_LOG_INFO, "beacon: the host published its camera");

    /* 8. The system that turns it. */
    memset(&system, 0, sizeof(system));
    system.id = id("beacon:systems.turn");
    system.name = str("beacon:systems.turn");
    system.update = turn;
    result = api->world_register_system(self, &system);
    if (result != FOUNDRY_OK) { (void)refused("beacon: system refused", result); goto fail; }

    say(FOUNDRY_LOG_INFO, "beacon: pillar, copper override, lamp and solid box are in the room");
    return FOUNDRY_OK;
fail:
    release_all();
    return result;
}

FOUNDRY_EXPORT void foundry_mod_shutdown(FoundryMod self)
{
    (void)self;
    stopped = FOUNDRY_TRUE;
    release_all();
}
```

Build it into the package's own directory, with the decoration the platform expects:

```sh
# macOS
zig cc -std=c99 -pedantic -Wall -Wextra -Werror -fPIC -dynamiclib \
    -I"$FOUNDRY/include" -o install/beacon/libbeacon.dylib beacon.c
# Windows, from any host
zig cc --target=x86_64-windows-gnu -std=c99 -pedantic -Wall -Wextra -Werror -shared \
    -I"$FOUNDRY/include" -o install/beacon/beacon.dll beacon.c
# Linux, from any host
zig cc --target=x86_64-linux-gnu -std=c99 -pedantic -Wall -Wextra -Werror -fPIC -shared \
    -I"$FOUNDRY/include" -o install/beacon/libbeacon.so beacon.c -lm
```

The library links nothing of Foundry's. It also compiles unchanged as C++17.

## 3. Run it

A player's mods live in the application's user data directory. On macOS:

```sh
MODS="$HOME/Library/Application Support/foundry-sandbox3d/mods"
mkdir -p "$MODS" && cp -R install/. "$MODS/"

cd "$FOUNDRY"
FOUNDRY_SANDBOX3D_PACKAGES=beacon:content \
FOUNDRY_SANDBOX3D_NATIVE=beacon:content \
    ./bin/sandbox3d
```

On Windows the directory is `%APPDATA%\foundry-sandbox3d\mods`; on Linux it is
`$XDG_DATA_HOME/foundry-sandbox3d/mods`, or `~/.local/share/…` without that variable.

`PACKAGES` selects the package. `NATIVE` is the player's consent to run its code, for this
run only, and is separate on purpose: with `PACKAGES` alone the stone pillar appears and the
log says `native beacon:content: content loaded; code not consented`. No content and no call
can grant that consent.

With both, the log shows:

```
info(mod): [beacon:content] beacon: destroying the host's floor was refused, as it should be
info(mod): [beacon:content] beacon: pillar, copper override, lamp and solid box are in the room
info(mod): [beacon:content] beacon: a ray from above lands on our box
info(sandbox3d): lighting: 4 lights, 92 shadow draws, 6 shadow culled
```

and the room holds two more objects and one more light than without the mod (46 draws and
4 lights against 44 and 3 in the same frame). You start facing the walker; both pillars are
to your left. Walk into either and you stop.

## 4. How the 3D calls work

**You do not draw. You keep objects, and the host draws them.** No mod code runs inside the
host's frame, so there is no draw call to make. `render3d_instance_create` makes an
*instance*: a model by content ID and a world matrix. It stays until you destroy it, and the
host submits every live instance each frame, after its own. You change it with
`render3d_instance_set_world`, `_set_material` and `_set_visible`, from `foundry_mod_init` or
from a system. A system runs once per fixed tick; a frame draws the last pose written.

**Everything is named by content ID.** There are no model or material handles to hold or
release: the host acquires what an instance names and lets go when the instance is
destroyed. That is also why another package overriding `beacon:materials.copper` changes your
pillar at the next content reload, with no code of yours involved.

**Material overrides are per slot.** A model's slots are its materials in order; the pillar
has one, slot 0. `render3d_instance_set_material(instance, slot, id)` replaces one for this
instance only, and a zeroed `FoundryContentId` clears it. An instance takes at
most eight overrides.

**Lights are retained the same way.** `kind` is 0 directional, 1 point, 2 spot; intensity is
lux for a directional light and candela for the others; direction is the rotation applied to
−Z. Three rules cost time if you do not know them:

* `memset` the struct to zero first. Reserved bytes that are not zero are refused.
* Every kind needs `0 <= inner_cone < outer_cone <= π/2`, including a point light that
  ignores the cone. A zeroed light is `FOUNDRY_ERR_INVALID_ARGUMENT`.
* Colour channels are 0 to 1; brightness goes in `intensity`. `casts_shadow` must be 0: the
  frame's one shadow is the host's.

A frame has room for 16 lights and the host's come first. A retained light that does not fit
is left out of that frame and counted, never an error.

**Transforms are the engine's.** `world_transform_set` gives an entity a local translation,
rotation and scale, and adds the component if it is missing. `world_parent_set(child,
parent, 0)` keeps the child's local transform; mode 1 keeps its place in the world.
`world_world_transform` reads the matrix the host last propagated. The host propagates once
per tick, before systems, so a system reads this tick's result and writes the next, as
`turn` does. Nothing draws an entity for you: copy the matrix to an instance yourself.

**Collision is queries and bodies, not dynamics.** `physics3d_raycast`,
`physics3d_shape_cast` and `physics3d_overlap` read the host's collision world. A miss is
`FOUNDRY_OK` with `hit` false. A filter is a `mask` of layers to consider and one body to
ignore; zero the struct, then set `mask`. Shapes are 0 sphere, 1 capsule, 2 box, with the
unused members left zero. Bodies are 0 static or 1 kinematic; nothing falls or is pushed.
`physics3d_character_create` and `_move` give you the same walking controller the player
uses, for a character of your own.

**The camera can be read.** `render3d_camera_get` gives the position, rotation, field of
view, clip distances and size the host last drew with. There is no call to set it.

## 5. Ownership

A mod may change or destroy only what it created. That is why every `_create` call takes
your `FoundryMod`.

| You pass | You get |
| --- | --- |
| a handle you created | `FOUNDRY_OK` |
| a live handle someone else created, to a call that changes it | `FOUNDRY_ERR_REFUSED` |
| a handle that was destroyed, or never existed | `FOUNDRY_ERR_INVALID_HANDLE` |
| any handle, to a read or a query | the answer |

Queries hand out other owners' handles all the time: a ray returns whatever it hit,
including the floor and the player. Step 2 of `foundry_mod_init` tries to destroy the floor
and checks that it is refused. A character's body cannot be changed through the body calls
even by its owner; move the character.

Outputs are written only on `FOUNDRY_OK`. When the host shuts down it releases whatever you
still own, so a missed destroy leaks nothing, but destroy what you made in
`foundry_mod_shutdown` anyway: another mod's objects are not yours to leave behind you.

## 6. What v6 does not do

Each of these is deliberate, and `design/public3d.md` §14 records what would bring it back.

* No drawing inside a frame, and no per-frame callback.
* No setting the camera.
* No animation calls: a skinned model is refused with `FOUNDRY_ERR_UNSUPPORTED` by
  `render3d_instance_create`.
* No meshes, materials or textures made at run time. They are content.
* No shaders.
* No mesh or hull shapes for bodies you create; a content prop is how a mod adds triangle
  collision.
* No shadow from a mod's light.
* No 3D in script mods.

## 7. When it does not work

* **`fpack: the work directory overlaps the package`**: the output directory contains the
  package directory. Move `install/` beside it, or pass `--work`.
* **`error: unknown schema 'sandbox3d:prop'`**, or **`'requires' names 'sandbox3d:content',
  which no granted dependency provides`**: a `--dependency` is missing. A package compiles
  against every package whose schemas or records it names.
* **The content appears but no code runs**: the log says whether consent was missing
  (`code not consented`), the library was not found beside the package (`could not open
  native library 'libbeacon.dylib': LibraryNotFound`; it must sit in the directory named
  after the `.fpk`), or `foundry_mod_init` returned an
  error, which is logged by name. A failed init keeps the package's content.
* **`FOUNDRY_ERR_INVALID_ARGUMENT` from a create or set call**: a field is not finite, a
  quaternion is not unit length, a matrix is not affine (its last row must be `0 0 0 1`), a
  reserved field is not zero, or the light rules above. `api->result_name` turns a code into
  its name; the example logs it with the step that failed.
* **`FOUNDRY_ERR_LIMIT`**: the host's bounds. The sample keeps at most 1,024 instances and
  8 retained lights.
* **F9 does nothing while the mod is loaded**: the sample refuses to rebuild a world that
  holds a native mod's registrations. Restart without `NATIVE` to load a save.

## Verification record

On 2026-10-02 this package was built in a directory outside the checkout with the commands
above, against a ReleaseSafe install that had been moved and made read-only, with `PATH`
reduced to the system directories and a disposable `HOME`:

* on macOS/Metal, 360 paced frames with no skipped frame, the three log lines above, 4 lights
  and 46 draws against 3 and 44 without the mod, and the instance set costing a median of
  0.0009 ms a frame;
* on the null backend, the same lines and counts headless;
* with `PACKAGES` alone, the content pillar and no code;
* the library compiled as strict C99 for macOS, Windows and Linux, and as C++17.

The Windows and Linux libraries were compiled and not run. What runs natively on Windows is
the in-repository `orbiter`, which uses the same calls
([`design/public3d.md`](../design/public3d.md), Step 6). The durable automated equivalents
are `engine/tests/public3d.zig`, which loads C99 mods through the real loader, and the
sample's own tests.
